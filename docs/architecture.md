# استودیو فیلم‌سازی شاهنامه — معماری و نقشهٔ راه

## ۱. تصمیم معماری

ComfyUI فقط «موتور اجرا» است و از دید استودیو پنهان می‌ماند. سه سرویس مستقل روی سرور ۱۱۷:

| سرویس | پورت | نقش |
|---|---|---|
| `image-api` | 8092 (یا همان 8090 موجود) | تولید/ویرایش عکس، سازگار با OpenAI Images |
| `ltx-video-api` | 8091 | تولید ویدیو LTX-2.5، سازگار با OpenAI Videos (Sora-style) |
| `tts-api` | 8093 | گفتار و کلون صدا، سازگار با OpenAI Audio |
| `studio` | 8099 | بک‌اند + UI استودیو (FastAPI + React) |

مزیت: هر زمان خواستیم ComfyUI را با پیاده‌سازی بومی (`ltx` / `diffusers`) عوض کنیم، فقط پشت همین APIها عوض می‌شود و استودیو دست نمی‌خورد.

### چرا ComfyUI فعلاً بماند؟
- پیاده‌سازی رسمی LTX-2.5 (دو مرحله‌ای، audio، latent upscaler، int8-convrot) در ComfyUI 0.42 هست.
- پشتیبانی از وزن‌های `comfy-int8-convrot` که برای H100 مناسب‌اند.
- بعداً می‌توان مستقیم با پکیج `ltx` رفت؛ قرارداد API ثابت می‌ماند.

## ۲. مدل داده (خلاصه)

```
Project ──┬── Character ──┬── CharacterImage (portrait/turnaround/expression)
          │               ├── WardrobeVariant (لباس/حالت)
          │               └── VoiceProfile (provider, voice_id, reference_audio)
          └── Script ── Scene ──┬── CastMember (Character + Variant)
                                └── Shot ── Render ── Asset(video/audio)
Asset: هر فایل رسانه‌ای با هش و متادیتا
```

## ۳. جریان کار

### تب ۱ — کاراکترها
1. توضیح کاراکتر («رستم») → ۴ پرترهٔ پیشنهادی با Flux.
2. انتخاب یکی → «ویرایش»:
   - ویرایش با پرامپت + تصویر مرجع (ReferenceLatent)
   - ویرایش ناحیه‌ای با ماسک (inpainting) — فاز بعد
   - لباس/حالت جدید به‌عنوان Variant
3. ساخت «برگهٔ کاراکتر»: نماهای جلو/سه‌رخ/تمام‌قد + چند حالت چهره → مرجع ثبات.
4. صدا: انتخاب voice یا آپلود نمونه → پروفایل صدا (بعداً کلون با Fish/ElevenLabs).
5. ذخیره با نام؛ کاراکتر در کل پروژه قابل استفاده.

### تب ۲ — سناریو
1. «طرح کلی» را کاربر می‌دهد (مثلاً: «نبرد رستم و اسفندیار، ۶ سکانس»).
2. LLM سناریوی ساخت‌یافته (JSON) می‌نویسد: سکانس، مکان، زمان، خلاصه، اکشن، دیالوگ‌ها، کاراکترها.
3. کاربر هر سکانس را ویرایش/تأیید می‌کند یا از صفر خودش می‌نویسد.
4. اتصال کاراکترها به هر سکانس (+ Variant مثلاً «شلوار آبی»).

### تب ۳ — صحنه‌ها و رندر
1. برای هر سکانس یک «فریم نگاه» (keyframe) ارزان با Flux ساخته و تأیید می‌شود.
2. هر شات با LTX-2.5:
   - t2v، یا i2v از فریم تأییدشده
   - پیوستگی: آخرین فریم سکانس قبل → فریم اول سکانس بعد
   - صدای محیط/دیالوگ با مدل AV
3. صف GPU، پیشرفت زنده، توقف/تکرار با seed.
4. خروجی: mp4 هر شات، سپس تدوین با ffmpeg + زیرنویس + صداگذاری فارسی.

## ۴. APIها (قرارداد)

```
POST /v1/images/generations      {prompt, size, seed, references[]}
POST /v1/images/edits            multipart: image, mask?, prompt
POST /v1/videos                  {prompt, size, seconds, seed, first_frame?, last_frame?, audio}
GET  /v1/videos/{id}             status/progress
GET  /v1/videos/{id}/content     mp4
POST /v1/audio/speech            {input, voice, language}
POST /v1/chat/completions        نوشتن/بازنویسی سناریو
```

## ۵. فازبندی

- **فاز ۰ (امروز):** رسیدن مدل، بالا آمدن دوبارهٔ ComfyUI، تست تولید عکس (۱۳ ثانیه) و آماده‌سازی API ویدیو.
- **فاز ۱:** بک‌اند استودیو + تب کاراکتر (تولید، انتخاب، ویرایش با مرجع، Variant، صدا، ذخیره) + UI.
- **فاز ۲:** سناریو با LLM + ویرایشگر سکانس + اتصال بازیگران.
- **فاز ۳:** رندر شات‌ها، پیوستگی، صف GPU، پیش‌نمایش.
- **فاز ۴:** تدوین نهایی، زیرنویس، صداگذاری، خروجی، نسخه‌بندی.

## ۶. ایده‌های پیشنهادی (فراتر از درخواست)

- **Style Bible پروژه:** یک «انجیل بصری» (سبک، پالت، دورهٔ تاریخی، لنز، نگاتیو، seed) که روی همهٔ تولیدها اعمال شود.
- **Look frame first:** اول فریم ثابت ارزان، بعد انیمیت؛ صرفه‌جویی زیاد در GPU.
- **Ingredients IC-LoRA:** LoRA رسمی LTX-2.5 برای چند کاراکتر/شیء مرجع در یک شات — دقیقاً برای ثبات بازیگر.
- **Seed book:** ذخیرهٔ seed هر کاراکتر/سکانس برای بازتولیدپذیری.
- **Prompt compiler:** تبدیل کاراکتر + لباس + مکان + زمان + دوربین + نور + اکشن به پرامپت نهایی LTX (با قالب مشخص).
- **دوزبانه:** نوشتن به فارسی، ترجمهٔ خودکار به پرامپت انگلیسی با حفظ نام‌ها و اصطلاحات شاهنامه.
- **Storyboard:** نمای تخته‌داستان و خروجی PDF از لیست شات‌ها.
- **Voice done right:** دیالوگ‌ها با برچسب کاراکتر → دوبلهٔ خودکار؛ TTS محلی فارسی (Piper) به‌عنوان پیش‌فرض بدون کلید API.
- **مدیریت GPU:** صف اولویت‌دار + قفل GPU + آزادسازی VRAM بین مدل تصویر و ویدیو (سرور مشترک است).
- **تاریخچه و مقایسه:** هر تولید نسخه می‌خورد؛ مقایسهٔ کنار هم و rollback.
- **برآورد هزینه/زمان** هر سکانس قبل از رندر.
- **امنیت و مالکیت:** ثبت هش/assets و واترمارک اختیاری.

## ۷. تصمیم‌های باز

1. استودیو روی سرور ۱۱۷ اجرا شود یا روی همین ماشین و فقط APIها روی سرور؟
   - پیشنهاد: روی ۱۱۷ (نزدیک به مدل‌ها و دیسک)، دسترسی با `http://<server-ip>:8099` یا تونل SSH.
2. تک‌کاربره با توکن یا چندکاربره؟
   - پیشنهاد: تک‌کاربره در فاز اول.
3. TTS: کلید Fish/ElevenLabs دارید یا با Piper محلی فارسی شروع کنیم؟
   - پیشنهاد: Piper برای شروع، Fish/ElevenLabs برای کلون بعداً.
4. LLM نوشتن سناریو: کدام سرویس/کلید؟
   - پیشنهاد: لایهٔ قابل‌تنظیم (OpenAI-compatible) تا هر endpoint‌ای وصل شود.
